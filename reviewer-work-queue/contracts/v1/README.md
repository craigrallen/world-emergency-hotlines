# Reviewer work queue and disposition audit v1 — STATIC/SYNTHETIC CONTRACT, NOT A WORKBENCH

This directory is a versioned read-only design/reference surface. It is not a live workbench, admin service, provider portal, account/auth system, intake route, persistence layer, telemetry system, or write API. Every identity, claim, queue item, URL, and event is conspicuously synthetic (`.invalid` and `syn_`) and non-canonical.

The v1 queue is deliberately single-item because its inputs are one claim and one review. It imports the existing provider-claim staging and independent-review trust boundary. Exact SHA-256 pins bind the checked-in synthetic claim, queue, and review bytes, and the reference model invokes `provider-claims/model.mjs`; it does not duplicate or weaken that validation. The sole assigned reviewer must exactly equal `review.reviewer.identity` and remain distinct from claimant and provider identities. Assignment cannot substitute another identity, and provider or claimant self-review fails closed.

`administrative_sequence` is an explicit clerical order only. It is not priority, urgency, risk, triage, geography, locality, country/category/hotline selection, crisis intent, provider prominence, or ranking, and it is never derived from any such input. Priority-like, risk, score, rank, and arbitrary metadata fields are prohibited by the closed schemas and model.

The complete v1 audit has exactly three events and one terminal disposition for the sole item, whose supplied queue state must be `disposed`. It binds the exact queue bytes with `queue_pin`. Each event commits its predecessor and deterministic event content hash, while `event_head_sha256` commits the final link; the only transitions are `not_queued → queued → assigned → disposed`. The checked-in, release-pinned static snapshot can therefore detect altered history bytes and broken links/head. This does not claim that arbitrary mutable logs are inherently append-only or prevent an authorized producer from replacing an entire untrusted snapshot. Duplicate, missing, reordered, skipped, cross-claim, or actor-substituted events fail closed. The terminal disposition must exactly match the item and pinned provider review. `rejected` and `needs_more_evidence` are never candidate eligible. `accepted_for_candidate` means only eligibility for the existing separate evidence, approval, dry-run, and application promotion gates.

Canonical mutation, verified status, ranking/search effects, and publication are always false. The contract performs no automatic verification or acceptance and cannot bypass promotion gates. It contains no real provider/customer/contact data, phone/email, crisis narratives or queries, locality or hotline selections, IP/referrer/user identifiers, availability/outcome/quality/security/compliance claims, pricing, billing, SLA, DPA, or support commitments.

Generated `/reviewer-work-queue/v1/` files are exact byte copies. Existing artifacts support GET, HEAD, and OPTIONS only; writes and unknown paths return 404. Public crisis information remains free.
