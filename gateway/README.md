# Managed API gateway foundation

This dependency-free Node 22 service is a local/synthetic foundation and is **not deployed**. Caddy publishes only the static `/gateway/v1` contracts. The free `/api/v1/**`, data, feeds, and widget remain unchanged and keyless; Docker does not launch or copy this runtime.

Startup is fail-closed. Configuration and key records must be closed plain own-property objects. The exported authentication boundary accepts an explicit validated mode and defaults to `production`; omitted, production, or invalid modes can never authenticate a `synthetic: true` record. Production peppers must be independently generated high-entropy secrets of at least 32 characters (synthetic fixtures may use an explicit 16+ character non-secret); peppers are never logged. Keys are `weh_live_<12 lowercase alphanumeric id>_<canonical 43-character base64url secret>`. Stored verifiers are canonical 32-byte HMAC-SHA-256 base64url values. IDs are globally unique: rotation means creating a **distinct ID**, overlapping two active records, then revoking the old ID. Revoked, explicitly expired, naturally expired (`now >= expires_at`), not-yet-valid (`now < not_before`), unknown, and malformed keys all return the same 401.

The only managed artifacts are canonical `/api/v1/manifest.json`, `/api/v1/records.json`, and `/api/v1/resolver.js`. There is no `/managed/v1/data`. A trusted descriptor is derived from `release/v1/release.json` and `release/v1/artifacts.json`, carries the release/dataset/index identities, and maps exact routes to paths, sizes, SHA-256 digests, and content types. Startup rejects symlinked ancestors/components, pins root/component/file device and inode identities, and verifies bytes. Every request rechecks component identity, uses `O_NOFOLLOW`, `fstat`, size, and digest. This assumes a trusted single writer; filesystem identity checks narrow replacement and symlink attacks but cannot make hostile concurrent mutation transactionally impossible on every filesystem.

Quota rates are tokens/second (`0 < rate <= 1000`) and bursts are integer tokens (`1..10000`), with the additional policy invariant `burst <= rate * 86400`. Thus `ceil(burst / rate) <= 86400` and every full-refill time fits the validated header contract. GET, HEAD, and authenticated 304 attempts each consume one token; OPTIONS, health, authentication failures, and authorization failures do not. `Retry-After` is whole seconds until one token. `RateLimit-Reset` is whole seconds until the bucket is full; all rate-limit headers are finite nonnegative decimal integers. The in-memory store is single-instance, clamps reverse-clock elapsed time to zero, and fails closed on invalid clocks, inputs, capacity, or custom-store results.

Requests must be query-free and bodyless. Any `Transfer-Encoding`, or `Content-Length` other than absent/`0`, returns generic 400 with `Connection: close`; malformed HTTP framing is closed by Node's parser. Exact known OPTIONS routes return 204. A configured allowed HTTPS origin receives `Access-Control-Allow-Origin` and `Vary: Origin` on success, 304, preflight, and known-route errors. A disallowed origin receives the same route status/capabilities without ACAO; credentials and wildcards are never enabled.

The server bounds headers, request/header/keepalive timeouts, requests per socket, connections, and active inbound requests. Shutdown stops acceptance, closes idle connections, and destroys remaining sockets after the configured bounded timeout. Logging constructs only the fixed privacy event schema; sink and sink-error callback exceptions are isolated, and no console fallback contains request data or secrets.
