# Verification operations

Phase 7 provides public intake and deterministic reviewer artifacts. It does not create verified records, provide counselling, test-call services, or change the canonical dataset.

## Public intake and privacy

Use the [hotline correction form](https://github.com/craigrallen/world-emergency-hotlines/issues/new?template=hotline-correction.yml) for an existing listing and the [provider/new-service form](https://github.com/craigrallen/world-emergency-hotlines/issues/new?template=provider-submission.yml) for an official organization. Issues are public. Never include personal crisis stories, health details, names of people seeking help, or other sensitive personal data. Submissions are unverified review leads; review and publication are not guaranteed. For immediate danger, contact local emergency services—the repository does not provide crisis counselling.

## Read-only monitor

The source monitor visits a bounded deterministic set of canonical public HTTP(S) website/source URLs. It rejects unsafe destinations and redirects, keeps TLS verification enabled, and caps redirects, bytes, request time, and URL count. Artifacts retain hashes and contact-presence observations, not page bodies, cookies, headers, or URL queries.

```sh
python scripts/source_monitor.py --as-of 2026-08-13 --limit 25 \
  --json-output /tmp/source-snapshot.json --markdown-output /tmp/source-report.md
```

An optional strictly validated `--previous` snapshot enables canonical-source-identity comparison. Previous URLs are keys only and never fetch inputs. Query- or fragment-bearing URLs and credentials are ineligible and are never requested or emitted. Every DNS answer must be public, the selected address is pinned through TCP, and the connected peer is revalidated; HTTPS retains the original hostname for SNI and certificate verification. A redirect, failure, changed hash, or missing listed contact is only a review prompt; it never proves validity or availability and never updates verification fields.

## Workbench

```sh
python scripts/freshness_report.py --as-of 2026-08-13 --json-report /tmp/freshness.json
python scripts/verification_workbench.py --as-of 2026-08-13 \
  --freshness /tmp/freshness.json --source-monitor /tmp/source-snapshot.json \
  --json-output /tmp/workbench.json --markdown-output /tmp/workbench.md
```

The workbench rejects unbound or malformed freshness, monitor, candidate, and approval artifacts, including unknown/duplicate IDs and hash/date/state mismatches. Candidate approvals bind both the canonical hash and deterministic candidate-bundle hash. The full freshness review set is retained in JSON while Markdown remains a bounded preview. Source outcome counts and degraded monitoring state are prominent in JSON, Markdown, and the scheduled job summary. Signals remain separate and produce reviewer actions rather than a quality/safety score; the workbench does not infer validity, eligibility, service scope, test-call status, or real-time availability.

Canonical publication remains exclusively behind the existing promotion candidate, explicit human approval, dry-run, and explicit apply route. These operations never mutate canonical data, candidates, approvals, or input reports. Outputs must be new paths and are never overwritten.

## Limitations

Automated fetching can be blocked, localized, stale, or misleading. Text matching can miss formatted contacts or find unrelated digits. A successful source observation means only that bounded page content was observed; it is not operational verification.

## Sustainable SEO monitoring

Prior retrieval has a strict CLI contract. Exit `0` means a compatible prior was published; exit `4` is the sole history-unavailable result; argparse exit `2` and local safety, path, output, publication, or schema/programming exit `3` are fatal. Only exit `4` continues monitoring: the shell writes a fixed bounded notice, removes and verifies the absence of partial prior payloads, and finalizes a complete first baseline. Remote API/download failures, malformed untrusted metadata or artifacts, no runs, no digest-era artifact, and bounded candidate exhaustion return `4`. Identifiers and local inputs/destinations are validated before remote access, so unsafe paths, aliases, symlinks, and pre-existing outputs remain fatal.

Repository maintainers own the weekly secretless monitoring workflow. It checks seven fixed routes on `https://worldhotlines.org`, then reuses the source monitor and freshness report. It cannot accept an arbitrary target, use repository secrets, run Search Console, or change canonical data. Compact public and source result states, the separate source snapshot, its strict member-hash manifest, and sanitized reports are retained for 90 days. The authentication envelope records the artifact run date separately from each monitor's nullable latest-successful observation date; public and source dates may differ, neither may exceed the run date, and the source-state date must equal the paired snapshot date. Prior completed runs are examined newest-to-oldest regardless of conclusion; incomplete, oversized, malformed, incoherent, or incompatible artifacts are skipped until a fully validated baseline is found. Eligible GitHub artifact metadata must include the immutable SHA-256 digest. The ZIP is streamed only from the fixed read-only artifact API endpoint, bounded by the declared compressed size, and accepted only when its computed digest matches GitHub metadata; the exact four-member archive then binds every state payload through the publication manifest. Old artifacts without GitHub digest metadata are skipped. A complete artifact from a failed regression run is intentionally accepted, allowing the next run to distinguish a continuing regression and later recovery. On monitor unavailability, its validated prior state is republished byte-for-byte without extending bounded history; source state and snapshot are carried only as a validated coherent pair. With no usable prior, a strict empty-baseline state and source snapshot keep the artifact complete without inventing recovery or history. New public or source regressions and monitor unavailability fail visibly, continuing identical regressions avoid repeated failure noise, and recovery remains visible in the bounded manifest-derived step summary. The source result strictly revalidates the complete current v3 snapshot and chronology before deriving alerts. With a usable prior source baseline, every current failed or blocked critical-cohort observation is a regression even when a record or canonical source URL is new; first-run and total-degradation policies remain separate. Ordinary noncritical content fingerprints, redirects, contact-presence changes, and source churn remain review signals and do not establish hotline invalidity. Source snapshot v3 stores sorted hashes of the full eligible record-ID/canonical-source identity population plus its count and digest, so rotating observation windows do not create false churn. Once GitHub archive provenance and the manifest member hash authenticate the prior snapshot bytes, its complete validated population is compared with a fresh reconstruction even across canonical byte changes, producing real added/removed counts. Deleted observations remain comparison-only and are never fetch inputs. A strict v2 reader retains one-time unavailable migration behavior. The standalone freshness and verification workflows are manual-only so weekly freshness is computed once.

Historical and current validation are deliberately separate. An authenticated historical snapshot must be exact schema v3 and is checked intrinsically for bounded canonical dates/hashes, full population count/digest, sorted unique observations, population membership, exact derived summaries, selection-policy bounds, safe URLs, and coherent outcome/change/triage fields. It is never reconstructed from newer canonical bytes. Only surviving current `(record ID, canonical source URL)` identities enter comparison; the complete authenticated populations enter churn. A newly produced current snapshot is additionally bound to a reconstruction from the exact current `hotlines.json` bytes, including its selected identities and critical-cohort cursor.

The manual verification workflow accepts only an exact canonical ASCII `YYYY-MM-DD` Gregorian `as_of` date that is no later than the current UTC date; an omitted value defaults to that UTC date. Invalid input fails before prior retrieval, artifact paths, monitoring, or publication. It uses the same history boundary in a successful-run-only window of at most 20 strictly parsed, completed, past runs. It tries them newest-to-oldest. For every candidate it requires exactly one non-expired, bounded artifact with the expected dated name and GitHub SHA-256 digest, streams and checks the declared byte size and digest, then verifies the embedded source member manifest and intrinsic snapshot schema. Missing, duplicate, expired, oversized, digest-mismatched, malformed, or incompatible remote candidates are cleaned up and skipped. History becomes unavailable only after the window is exhausted; unsafe local paths or invocation errors remain fatal.

Source selection reserves a small deterministic `emergency`/`suicide_crisis` cohort and rotates the remaining bounded window by ISO week. Snapshot identity is the stable record ID plus the current canonical source URL. A canonical-file hash change is reported but does not discard matching observations; deleted or unknown prior identities are churn metadata and are never fetch inputs.

The 90-day freshness threshold is an operational review cadence/SLA. It is not a validity cutoff and never establishes that a listed service works, is safe, or is available. All public, source, freshness, sitemap, analytics, and sampled inspection observations are review prompts only. This is especially important for this YMYL dataset: monitoring must not promote, remove, verify, or make availability claims about a record.

### Local Search Console procedure

`scripts/search_console_monitor.py` is intentionally excluded from GitHub Actions. An operator must supply a quota-project identifier and absolute output paths outside the checkout. The script captures an Application Default Credentials access token from `gcloud`, never prints or stores the token or ADC material, and makes only fixed read-only calls for `sc-domain:worldhotlines.org`.

```sh
python scripts/search_console_monitor.py \
  --quota-project PROJECT_IDENTIFIER \
  --as-of 2026-08-15 \
  --json-output /absolute/external/monitor-output.json \
  --markdown-output /absolute/external/monitor-output.md
```

Use an operator-managed external directory with restrictive permissions and retention appropriate to local policy. Search Analytics is explicitly requested with `dataState=final`, whose documented contract includes only finalized data. A conservative four-complete-day reporting lag makes the current 28-day window end at `as_of - 4 days`; the prior window is the immediately preceding 28 days. Final responses carrying incomplete-boundary metadata are rejected. Because zero-activity dates are omitted under final semantics, missing date rows aggregate as zero. Only bounded completeness counts and date-only aggregates are retained; query text, page/query pairs, geography, and device rows are never requested or retained. Click decline requires a prior aggregate of at least 20 and a decline of at least 50%; impression decline requires at least 200 prior impressions and a decline of at least 40%. Exact boundaries alert, while zero/thin baselines and smaller fluctuations do not. At most five deduplicated fixed URLs are inspected sequentially. Sitemap registration/processing is reported separately from indexing. `/status` accepts only sampled exact documented noindex-exclusion evidence and creates a regression issue only for affirmative sampled indexed evidence. Ambiguous, unknown, incomplete, or contradictory `/status` evidence remains bounded informational counts in JSON and Markdown; it neither changes an otherwise healthy status nor suppresses a separate affirmative indexed finding. Indexable samples likewise require affirmative indexed evidence. None of these samples is generalized into a site-wide conclusion. Transport or schema failure remains `unavailable`, never a zero or healthy observation. Missing tooling/ADC, an empty token, authorization failure, disabled API, quota-project configuration, and property permission denial are distinct sanitized failures.

Output parents are pinned by directory identity while fully fsynced temporary files are staged and published with atomic no-replace links. Supported filesystems do not provide a portable transaction spanning both JSON and Markdown destinations. If a later publication fails, the helper rolls back only earlier destinations whose inode identity proves this invocation created them; it never overwrites or removes a pre-existing or racing destination. Parent replacement or symlink swaps fail closed, and all remaining staging files are removed through the pinned directory descriptor.
