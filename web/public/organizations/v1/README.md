# Organization control-plane v1 foundation design contract — not deployed

This directory is a static, versioned **foundation/design contract** and deterministic synthetic harness. It is not a signup, administration, authentication, key-management, widget-management, or write service. No pricing, SLA, billing, customer collection, domain-ownership verification, or active signing is provided or implied.

The existing public site, API, feeds, widget, and data remain free and keyless. Existing local `/managed/v1/**` behavior is outside this contract and unchanged.

`model.schema.json` is a closed JSON Schema Draft 2020-12 bundle. `openapi.json` describes illustrative future dynamic URLs under `/future-admin/organizations/v1`; those routes are not deployed. The separately published `/organizations/v1/**` URLs serve only byte-identical static contract, documentation, and synthetic fixture files with GET/HEAD and read-only OPTIONS behavior. The source-only `../model.mjs` module is executable reference code for repository verification; it is deliberately outside the versioned public artifact manifest and is not an exported product API.

All fixture identifiers are reserved `*_demo_*` values and all origins use `.invalid`. Fixtures contain no people, contacts, network observations, raw credentials, secrets, subscribers, crisis activity, directory records, location or behavioral dimensions.

The top-level fixture is one internally consistent read model at `effective_at`. Each transition scenario is fully discriminated: accepted commands contain accepted results, accepted hosted-config audit events, and the exact changed state; rejected commands contain rejected results, rejected hosted-config audit events, and an exact `unchanged:true` pointer/lifecycle snapshot. Audit scope in this slice is hosted-config activation only. Role and key audit event contracts are intentionally deferred until a semantic command harness exists. Commands with valid structure but unknown organization/project bindings are rejected and may return a null `active_config_version_id`; malformed models or commands throw the stable programmer/configuration error `invalid control-plane input`. The harness evaluates transitions purely and atomically: rejection returns an equal state; acceptance changes only the project pointer, project update timestamp, and the two mutable lifecycle envelopes.

Hosted configuration `content` is immutable. `content_digest` is unsigned design metadata containing SHA-256 over canonical content only; it authenticates neither lifecycle nor publisher identity. `lifecycle` is explicitly mutable and excluded from the digest. `signature_metadata.algorithm` remains `none`; no signing service exists.

Lifecycle is closed: active projects require active organizations, one active configuration, matching pointer, and active parents for active/pending keys and active project grants. A rollback target must be a distinct retired version with a lower revision that is reached by following the exact `previous_version_id` chain from the current active version. Suspended projects retain a pointer to a retired version owned by the same organization/project and listed in that project's hosted versions; they have no lifecycle state `active`, active/pending key, or active project grant. Archived projects have a null pointer and no active lifecycle or authorization. Suspended/archived organizations cannot contain active projects, active/pending keys, active grants, or accepted commands; archived states are terminal in this static model.

Owner and admin roles are organization-scoped only (`project_id:null`); developer and viewer roles are project-scoped only. Permissions are exact per role. Every active organization has at least one active owner, and duplicate active assignments for the same principal, organization, project, and role are forbidden.

`keyref_demo_*` values are control-plane reference IDs, not raw gateway credentials or gateway key-record IDs. Reference metadata maps conceptually; no credential/key-record binding is implemented. Active and pending references require active parents. Revoked and suspended references cannot predate `not_before`; expired references must expire by `effective_at`. Rotation is a single non-forking, acyclic predecessor chain within one organization/project/API major with exact permissions and quota. Each predecessor is chronologically earlier and revoked or expired before an active successor fixture is valid.
