# Internal security/privacy evidence inventory

Internal-only marker: `internal-security-privacy-evidence-only/v1`.

This is repository-internal deterministic regression evidence. It inventories only narrow static controls and limitations already represented by tracked source bytes. It is not a public assurance, certification, completed threat model, security policy, privacy policy, DPA, legal opinion, external assessment, penetration test, cryptographic assurance, availability statement, contact promise, vulnerability SLA, or commercial offer. It makes no claim of security, privacy, WCAG, or legal compliance.

Every assertion cites one or more Git-tracked paths from the finite `sources` map. The map binds each path to its raw-file SHA-256 digest. Each complete production validation and source-map generation requires exact equality of argv-only `git ls-files -s -z` snapshots taken before and after the operation. After each stable no-follow descriptor read, the verifier also obtains the same path's exact Git index blob with an argv-only Git subprocess and requires byte-for-byte equality, including for the inventory itself. It uses strict UTF-8 and JSON decoding, retained pre-read pathname ancestor metadata with post-read identity/stability comparison, ancestor and leaf symlink rejection, and canonical file-identity deduplication. These pre/post pathname observations detect replacements that occur during the observed read window; Node does not provide portable `openat` traversal, so this is not absolute race freedom or a hostile-concurrency guarantee. The verifier also rejects schema changes, duplicate identifiers/commands/check references, unknown statuses, unbound evidence, verified assertions without a named check, and gap entries that cite checks. Status is limited to `verified_static`, `manual`, `not_assessed`, and `held`; only the first means a named repository check inspects the stated static contract.

Run `npm run update:security-privacy-evidence-sources` from `web/` after intentionally reviewing a bound source change, then replace only the `sources` object with the printed object. Run `npm run test:security-privacy-evidence` for adversarial fixtures and `npm run verify:security-privacy-evidence` for the build, inventory, and nonpublication checks.

The inventory deliberately records manual, unassessed, and held boundaries. Static repository checks do not establish runtime infrastructure behavior, penetration-test results, operational response, hotline or service availability, legal compliance, data retention behavior outside these static routes, or third-party/provider practices.

The complete `reviews/` tree is excluded from the Docker build context. Web `dist` verification scans for the listed stable markers and exact complete artifact hashes, including exact copies renamed arbitrarily. It does not claim to recognize modified copies after their markers are removed. The final-image check scans the served root `/srv` for listed paths and markers and probes representative routes; it does not scan OS binaries outside `/srv`, because only `/srv` is served. The image check does not claim arbitrary-name exact-hash scanning.
