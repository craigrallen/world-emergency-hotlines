# Internal technical due-diligence evidence index

Internal-only marker: `internal-technical-due-diligence-evidence-only/v1`.

This is a non-authoritative, repository-internal navigation and regression artifact. It composes already-delivered evidence without upgrading any source into a public assurance, certification, conformance statement, audit opinion, security assessment, legal opinion, availability statement, or sales artifact. Its `proves_narrowly` text describes only facts represented by exact bound source bytes. Every entry separately records what is not proved and the next qualified or manual gate.

The finite `sources` map binds raw tracked bytes with SHA-256. The verifier reuses the security/privacy evidence reader for strict UTF-8 and JSON, duplicate-member rejection, safe canonical paths, symlink and duplicate-file-identity rejection, stable no-follow reads, exact Git-index parity, and whole-index drift checks. The pathname observations detect replacements during the observed read window; they are not portable `openat` traversal, absolute race freedom, or a hostile-concurrency guarantee.

The checked-in schema is an exact, closed Draft 2020-12 specification and is compiled with the repository's Ajv 2020 dependency. It expresses safe source property names, closed objects, the exact ordered six-domain tuple, fixed status tuple, finite array bounds, field types, and string/digest forms. Runtime-only invariants are separately tested and documented because JSON Schema cannot express them here: lexically sorted source keys, exact one-to-one source/artifact coverage, at least eight non-`verified_static` status gaps, reading and hashing the tracked source bytes, and rejection of unsupported assurance language. This is exact checked-in-schema/specification parity plus runtime-only invariants, not full semantic parity.

An implementation-owned immutable v1 inventory pins the exact ordered artifact paths for every domain independently of `index.json`: release integrity, deployment/build, accessibility, multilingual qualification review, security/privacy, and internal control integrity. Exact union equality between those domain inventories and `sources` consequently pins the complete v1 source-path inventory while preserving every domain assignment. `index.json` cannot hash itself without a circular digest. Instead, a complete load reads both index and schema through the tracked stable no-follow reader, requires worktree/index equality, retains pre/post pathname identity observations, and requires an unchanged whole-index snapshot while schema and runtime validation complete. All listed sources must be used exactly once by the domain inventory.

Run `npm run update:technical-due-diligence-sources` from `web/` only after manually reviewing intentional source changes, then replace only the printed `sources` object. Run `npm run test:technical-due-diligence` for adversarial tests and `npm run verify:technical-due-diligence` for build, verification, and nonpublication coverage.

The artifact contains no raw or sensitive evidence. It links only repository paths and narrow descriptions. The complete `reviews/` tree remains excluded from the Docker context. The dist check scans stable markers and exact current evidence-file hashes, including arbitrarily renamed exact copies. The locally built deployment-image check scans the served `/srv` tree for a finite set of plausible technical due-diligence paths and stable markers and probes finite candidate routes. It does not perform arbitrary-name exact-copy hashing in the image, recognize modified marker-stripped copies, inspect files outside served `/srv`, or prove anything about an externally deployed image.
