# Qualified review queue

Licensing remains held. No counsel contact or approval has occurred. Before activation, qualified reviewers must decide: licensed field/right boundaries; deletion and aggregate-retention windows; controller/processor roles; audit scope and notice; suspected-leak notification deadline; token/key cryptography and rotation/revocation operations; false-positive investigation and appeal; tenant/app authentication; incident response; jurisdiction, remedies, accessibility, availability, DPA/SLA/security representations; and whether any managed delivery is permissible at all.

Security review must threat-model token disclosure, replay, clock manipulation, shared caches, proxy/CDN behavior, key compromise, bounded key-registry distribution, tenant isolation, aggregate poisoning, and outward-in false matches. Privacy review must decide whether tenant/app attribution and the proposed coarse buckets/count caps are proportionate, set retention, and verify that the closed telemetry schemas and downstream stores cannot accept forbidden dimensions or contact payloads. Safety review must re-prove exact byte identity for every canonical hotline field and routing/fallback semantics. Legal decisions about evidentiary weight, investigation, notice, appeal, remedies, jurisdiction, and whether machine-readable token visibility is acceptable all remain held for qualified review.

Reference decisions: normal issuance uses cryptographically secure random nonces; deterministic injection is accepted only with `synthetic_fixture:true`, and `response_counter` is absent. Verification requires a shared cross-process durable atomic claim service retaining tenant/key/token and tenant/key/nonce through expiry plus skew; there is no local default. Bounded authenticated active/revoked registries cover keys, registered tenant/app/version tuples, issued presentations, and issued metadata. Opaque metadata derivation includes tenant, app ID, app version, record revision, and release revision; registry attribution is accepted only after reproducing the matched digest from that complete identity, metadata type, and issuance key. Calendar-hour evidence must use an exact canonical UTC hour that round-trips through the runtime calendar. Credentials select identity, the service creates IDs, signed evidence is normalized before analysis, and failures close. These are prerequisites, not approval.

Flat volume first aggregates per tenant/app/distinct hour, sorts hours, and requires three consecutive one-hour buckets with equal positive totals. Duplicates within an hour, gaps, zeroes, and unequal totals do not qualify. Evidence remains corroborating or ambiguous, never conclusive.

All input string ceilings are UTF-8 byte ceilings. Draft 2020-12 `maxLength` counts Unicode code points and is therefore not used to represent those safety limits. The schema's normative `x-maxUtf8Bytes` extension and recursive resource-bound extensions must be registered by validators; the repository verifier machine-checks them against runtime and HTTP-contract limits, including multilingual boundary cases.
