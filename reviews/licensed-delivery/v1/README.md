# Internal licensed-delivery anti-cache foundation v1

This entire directory is repository-internal and synthetic. It is a reference contract for a possible future authenticated runtime, not an active service, license, offer, legal advice, telemetry system, or claim of enforcement. The current public/keyless/static API remains public and cacheable. Qualified legal, privacy, and security review is required before use.

The package binds canonical safety-critical bytes to record and release revisions, derives tenant-specific opaque metadata with domain-separated HMAC, signs short-lived tenant presentations, and verifies only keys selected from a bounded active/revoked registry by the signed `key_id`. It validates privacy-bounded, tenant/app-attributable observations and emits carefully labelled non-conclusive signals. Render-to-fetch ratios are computed only within a tenant/app/hour bucket; ratios above one are corroborating, while equal, lower, unmatched, and zero-denominator cases remain ambiguous. `http-contract.json` is the normative machine-verified future HTTP contract. `terms.counsel-draft.md` is an internal draft only.

Run from `web/`: `npm run verify:licensed-delivery`. The dependency-free runtime and verifier reject unknown inventory entries, symlinks, path drift, schema/fixture/contract drift, unsafe variation, privacy dimensions, malformed/oversized input, replay, expiry and clock abuse. The closed Draft 2020-12 bundle mirrors the strict runtime validators. Uncommitted review remains executable without pretending it is clean-checkout evidence.

The future runtime must derive tenant, registered app, and version from authenticated credentials; clients may not select them. It generates observation and acquisition IDs server-side and domain-signs every closed evidence object with a bounded active/revoked observation-key registry. Analysis accepts only the exact deeply frozen objects returned by verification, never raw, copied, or modified client JSON. Render/presentation evidence binds every tenant/app/version/revision/time/key field to a bounded issued-presentation ledger and an active bounded presentation-key registry. Hour buckets must overlap token validity. All schema enums are mirrored by runtime checks; version is present in every comparison and grouping key.

Presentation verification requires an explicit atomic replay store. One operation claims both tenant/key/token and tenant/key/nonce and retains them through expiry plus clock skew. Missing, unavailable, partial, or rejected claims fail closed. A deployment requires a shared cross-process durable, linearizable or uniqueness-enforcing store; process-local sets do not satisfy the contract. Production nonces are cryptographically random. Deterministic nonce injection is fixture-only behind `synthetic_fixture:true`; caller counters are not part of production issuance.

Outward captured-artifact and binary evidence contain only artifact SHA-256, fixed-enum acquisition provenance, service-generated acquisition ID, fixed-enum scan method, registered scan version, matched metadata digest or null, and evidence authentication—never artifact bytes or hotline/contact data. Positive matches require the trusted metadata registry; authenticated non-matches are neutral. App binaries remain a separate evidence type. The CLI intentionally has no `verify` command because JSON cannot provide the mandatory durable atomic replay adapter; its remaining issue/analyze paths are synthetic reference helpers only.
